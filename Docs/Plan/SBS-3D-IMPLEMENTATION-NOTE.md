# XREAL 1S and Unreal SBS 3D Implementation Note

작성일: 2026-04-22

관련 문서:

- `Docs/Plan/PLAN.MD`
- `Docs/Plan/LEVEL-CANDIDATE-PROJECT-FIT.md`

## 1. 문서 목적

이 문서는 아래 질문에 답하기 위해 작성한다.

1. XREAL 1S에서 3D로 볼 영상을 Unreal 프로젝트에 넣을 수 있는가
2. 일반 2D 영상 재생만 구현해도 되는가
3. 진짜 SBS 3D 영상이 필요하다면 Unreal에서는 어떤 방식으로 구현하는가

이 문서는 현재 프로젝트와 다음 프로젝트 모두에 참고 가능한 기술 판단 문서다.

## 2. 핵심 결론

먼저 결론부터 정리하면 다음과 같다.

### 결론 A. 일반 2D 영상 머티리얼 교체만으로도 "영상 재생"은 가능하다

즉, Unreal에서 스크린/벽면/오브젝트 표면에 영상을 틀기 위해서는  
기본적으로 `Media Plate` 또는 `MediaTexture + Material` 구조만 있으면 된다.

### 결론 B. 하지만 "진짜 SBS 3D"는 일반 2D 영상만으로 해결되지 않는다

`SBS 3D`는 좌안/우안용 정보가 분리된 콘텐츠가 필요하다.  
즉, 원본이 스테레오 기준으로 준비되어 있어야 가장 정확하다.

### 결론 C. XREAL 1S 자체의 2D->3D 기능을 이용하면 2D 영상도 3D처럼 시험해볼 수 있다

XREAL 1S는 공식적으로 `glasses-side 2D-to-3D`를 강조하고 있다.  
즉, 별도 소프트웨어 없이도 기기 쪽에서 2D 영상을 3D처럼 변환하는 방향이 가능하다.

다만 이것은

- "원본 SBS 3D"와 동일한 품질을 보장하지 않으며
- 영상 종류에 따라 효과가 다르게 느껴질 수 있다

## 3. XREAL 1S에서 중요한 점

공식 자료 기준으로 확인되는 핵심은 다음과 같다.

### 3.1 3D 모드는 호환 콘텐츠 전제가 있다

XREAL One 시리즈 공식 가이드에서는

- 3D Mode는 `16:9 screen sizes`에서 사용 가능
- `compatible 3D content`가 필요

라고 안내한다.

즉, 전통적인 의미의 3D 모드는 여전히 콘텐츠 형식의 영향을 받는다.

### 3.2 XREAL 1S는 별도로 2D->3D 기능을 강조한다

XREAL 1S 공식 페이지는

- `The World’s First Glasses-Side 2D-to-3D`
- `No Software. Just Plug and Play.`

를 강조한다.

이 의미는 다음과 같다.

- Unreal이 반드시 먼저 SBS 콘텐츠를 만들지 않아도
- 일단 일반 2D 영상 재생 시스템을 구현한 뒤
- XREAL 1S의 기기 기능으로 3D 체감을 시험할 수 있다

### 3.3 실무 해석

따라서 XREAL 1S를 쓰는 프로젝트에서는 아래 두 개를 구분해야 한다.

1. `기기 변환 기반 3D`
2D 영상 재생 후 XREAL 1S가 변환

2. `콘텐츠 원본 기반 SBS 3D`
처음부터 좌안/우안이 분리된 영상을 재생

이 둘은 구현 난이도와 결과 안정성이 다르다.

## 4. "일반 2D 영상 머티리얼만 교체하면 되나?"에 대한 정확한 답

### 4.1 영상 재생 자체만 보면 된다

`된다.`

언리얼에서 오브젝트 표면에 일반 영상을 재생하는 것은 표준적인 기능이다.

대표 방식:

- `Media Plate`
- `Media Player + Media Texture + Material`

### 4.2 XREAL 1S에서 3D 체험을 한 번 해보는 목적이라면 된다

`된다.`

현재 단계에서 꼭 한 번 넣어보고 싶다면,

1. Unreal에 일반 2D 영상 재생 시스템을 만든다
2. XREAL 1S의 2D->3D 기능으로 실제 체감을 테스트한다

이 방식은 매우 현실적이다.

### 4.3 하지만 "진짜 SBS 3D 지원"이라고 부르기엔 부족하다

`안 된다.`

왜냐하면 일반 2D 영상은 좌안/우안 스테레오 정보가 없기 때문이다.

즉,

- 일반 2D 영상 재생 = 가능
- XREAL 1S로 3D처럼 보기 = 가능
- 이걸 곧바로 진짜 SBS 3D 구현이라고 보기 = 불가

## 5. Unreal에서 가능한 구현 방식

## 5.1 방식 A. 일반 2D 영상 재생 + XREAL 1S 기기 변환

### 개념

Unreal은 평범한 2D 영상을 재생한다.  
XREAL 1S가 기기에서 이를 3D처럼 변환해 본다.

### 구현 방법

- Unreal에서 스크린 Mesh 준비
- `Media Player`
- `Media Texture`
- 영상 출력용 Material
- 스크린 Mesh 또는 `Media Plate`에 적용

### 장점

- 가장 구현이 쉽다
- 현재 프로젝트에 빠르게 넣어볼 수 있다
- 기존 영상 재생 시스템이 그대로 남는다
- MVP 이후에도 일반 전시 영상 재생 기능으로 재사용 가능하다

### 단점

- 진짜 스테레오 원본이 아니므로 깊이감이 항상 자연스럽지 않을 수 있다
- 영상 종류에 따라 3D 효과가 약하거나 부자연스러울 수 있다
- 최종 납품 품질을 이 방식 하나에 의존하는 것은 위험하다

### 실무 판단

이 방식은 `1차 검증용`으로 매우 좋다.

즉,

- "XREAL 1S에서 전시 영상이 어느 정도 체감되나?"
- "우리 콘텐츠 톤에서 2D->3D 변환이 먹히나?"

를 가장 싸고 빠르게 확인하는 방법이다.

## 5.2 방식 B. 사전 제작된 SBS 3D 영상 재생

### 개념

미리 제작된 SBS 영상을 Unreal에서 그대로 재생한다.

일반적으로 SBS는 아래 두 형태가 흔하다.

- `Full SBS`
- `Half SBS`

이 둘은 업계/커뮤니티에서 흔히 쓰이는 포맷 구분이며,  
최종 해상도와 선명도 차이가 있다.

### 구현 방법

- 사전 제작된 SBS 영상 파일 준비
- Unreal `Media Player`로 재생
- 출력 화면은 일반 영상처럼 재생하되, 실제 관람은 XREAL의 3D 모드로 수행

### 장점

- 결과가 예측 가능하다
- 원본 제작 단계에서 원하는 좌/우 시차를 제어할 수 있다
- XREAL 1S 기기 변환보다 일관된 결과를 얻기 쉽다

### 단점

- SBS 영상 제작 파이프라인이 추가된다
- 파일 크기가 커질 수 있다
- 영상이 상호작용형이 아니라 고정 콘텐츠 중심이 된다

### 실무 판단

이 방식은 `전시용 최종 퀄리티`를 노릴 때 가장 현실적이다.

즉,

- 정해진 전시 영상
- 정해진 연출 타이밍
- 반복 재생

같은 시나리오에는 매우 적합하다.

## 5.3 방식 C. Unreal 실시간 스테레오 렌더 -> SBS 출력

### 개념

Unreal이 좌안/우안용 시점을 각각 렌더링하고,  
이를 실시간으로 합쳐 SBS 프레임을 만든다.

### 가능한 구현 방향

- 좌안용 Camera 또는 SceneCapture
- 우안용 Camera 또는 SceneCapture
- 각 Eye를 Render Target에 출력
- 머티리얼이나 후처리에서 좌/우 이미지를 SBS 형태로 결합
- 최종 스크린에 출력

### 장점

- 실시간 상호작용형 콘텐츠에 대응 가능
- 언리얼 씬 그 자체를 스테레오로 만들 수 있다
- 영상뿐 아니라 실시간 이벤트/캐릭터 반응까지 연동 가능하다

### 단점

- 구현 난이도가 가장 높다
- GPU 비용이 크게 증가한다
- 좌/우 카메라 동기화, 포스트프로세스 일관성, 렌더 타이밍 관리가 필요하다
- 현 프로젝트 MVP 범위를 넘어서기 쉽다

### 실무 판단

이 방식은 현재 프로젝트의 첫 단계에는 과하다.

즉,

- "한 번 넣어보고 싶다"
- "XREAL에서 되는지 보고 싶다"

수준이라면 이 방식으로 바로 가는 것은 권장하지 않는다.

## 6. 현재 프로젝트에 대한 권장 순서

현재 프로젝트 기준으로는 아래 순서가 가장 맞다.

### Step 1. 일반 2D 영상 재생 시스템 구현

- 특정 스크린/오브젝트/벽면에 영상 재생
- 상호작용 시 재생 시작/정지
- 패널 명령 또는 트리거와 연결

이 단계는 XREAL과 무관하게도 전시 확장 기능으로 가치가 있다.

### Step 2. XREAL 1S로 2D->3D 체감 테스트

- 일반 2D 영상 몇 개를 실제로 재생
- XREAL 1S에서 Real 3D 체감 확인
- 어떤 장면에서 잘 먹히고 어떤 장면에서 별로인지 기록

### Step 3. 품질이 부족하면 사전 제작 SBS 영상 도입

- 핵심 데모 영상만 선별
- SBS 버전 별도 제작
- Unreal에서는 재생만 담당

### Step 4. 정말 필요할 때만 실시간 스테레오 렌더 검토

이 단계는 다음 프로젝트 또는 별도 R&D 범위로 보는 것이 맞다.

## 7. 전시 프로젝트 관점에서 어떤 방식이 맞는가

### 가장 현실적인 방식

`2D 영상 재생 시스템 + XREAL 1S 실제 테스트`

이 방식은

- 개발 비용이 낮고
- 현재 프로젝트 범위에 맞고
- 실패해도 일반 영상 재생 기능이 그대로 남는다

### 최종 퀄리티 우선 방식

`사전 제작 SBS 영상 재생`

이 방식은

- 최종 연출 통제가 좋고
- 전시 시나리오 반복 재생에 강하다

### 고난도 실험 방식

`실시간 스테레오 렌더`

이 방식은 현재 프로젝트에서는 우선순위가 낮다.

## 8. 구현 시 주의사항

### 8.1 화면 비율

공식 가이드 기준으로 3D Mode는 `16:9` 조건이 중요하다.  
따라서 영상 재생 스크린이나 출력 파이프라인도 비율 관리가 중요하다.

### 8.2 메모리와 로딩

SBS 영상은 일반 영상보다 파일 크기와 디코딩 비용이 커질 수 있다.  
따라서

- 프리로드 여부
- 스트리밍 정책
- 반복 재생 정책

을 같이 설계해야 한다.

### 8.3 영상 종류에 따른 체감 차이

XREAL 1S의 기기 변환은 콘텐츠에 따라 결과 편차가 클 수 있다.

예를 들어

- 전경/배경 분리가 명확한 장면
- 카메라 움직임이 너무 복잡하지 않은 장면
- 피사체 깊이 차이가 분명한 장면

은 상대적으로 유리할 수 있다.

반대로

- 평면적인 UI 영상
- 빠른 컷 편집
- 복잡한 파티클, 글리치, 과한 포스트프로세스

는 기대보다 효과가 약할 수 있다.

### 8.4 전시장 관람 UX

기술적으로 3D가 되더라도,

- 관람자가 어느 위치에서 봐야 하는지
- 어떤 장면이 3D 포인트인지
- 상호작용 후 얼마 동안 영상을 보여줄지

가 명확해야 실제 전시 경험이 좋아진다.

## 9. 지금 시점 최종 판단

현재 프로젝트에서 가장 합리적인 판단은 아래와 같다.

1. 일반 2D 영상 재생 시스템은 바로 구현 가치가 있다
2. XREAL 1S의 2D->3D 기능으로 한 번 시험해보는 것도 충분히 가치 있다
3. 하지만 이것만으로 진짜 SBS 3D 지원이 완성된 것은 아니다
4. 최종 전시 품질이 중요하면 결국 사전 제작 SBS 영상을 검토하는 편이 맞다
5. 실시간 스테레오 렌더는 현재 프로젝트 MVP 범위를 넘길 가능성이 높다

한 줄 결론:

`현재 프로젝트는 2D 영상 재생부터 만들고, XREAL 1S로 검증한 뒤, 필요하면 SBS 원본 영상으로 고도화하는 순서가 가장 실무적이다.`

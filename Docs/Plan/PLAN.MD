# 1-Character Interactive Exhibition Prototype 계획서

작성일: 2026-04-26

## 0. 현재 결론

이 프로젝트는 `모바일 패널 -> ASP.NET 로컬 서버 -> Unreal Engine 클라이언트`로 이어지는 1캐릭터 인터랙티브 전시 프로토타입이다.

현재까지는 기본 MVP의 핵심 흐름이 거의 성립했다.

- 패키징된 Unreal exe 실행
- ASP.NET 서버 자동 실행 구조
- 모바일 패널 정적 배포 및 노트북 IP 접속
- Happy, Aged, Classic 같은 감정/스테이지 명령 실행
- 조이스틱/터치 기반 이동 및 회전 입력
- 서버에서 모바일 패널 접속 URL/QR 생성

다만 포트폴리오 제출 전에는 아래가 아직 남아 있다.

- 패키징 경로 최종 정합성 재확인
- 선택한 Unreal 레벨/시연 구간 고정
- 감정/애니메이션/스테이지 반응의 최종 연출 품질 확인
- 1~2분 데모 시나리오와 영상 정리
- 챗봇/RAG 확장 여부 결정 및 구현

## 1. 프로젝트 목표

휴대폰 웹 패널을 리모컨처럼 사용해 PC에서 실행 중인 Unreal 캐릭터와 전시 공간을 실시간으로 제어한다.

목표 경험:

```text
모바일 입력
-> 서버 명령 해석
-> Unreal 캐릭터 반응
-> 전시 공간 연출 변화
-> 관람자가 즉시 변화를 확인
```

초기 MVP는 1캐릭터 기준으로 완성하고, 이후 2캐릭터, MetaHuman, LLM/RAG 전시 가이드, 음성, motion generation 실험으로 확장한다.

## 2. 기준 MVP 범위

포함:

- 1캐릭터
- 모바일 웹 패널
- 감정 명령
- 애니메이션 명령
- 이동/회전 입력
- 스테이지 이벤트
- 로컬 서버
- Unreal 패키징 실행
- 같은 네트워크의 모바일 접속
- QR 또는 URL 안내

제외:

- 2캐릭터 상호작용
- MetaHuman 고도화
- 실시간 얼굴 추적
- WebRTC/gRPC 실전 적용
- 복잡한 음성 인식/TTS
- 실시간 motion generation
- 장기 운영용 계정/인증 시스템

## 3. 현재 작업물과 계획의 차이

| 항목 | 원래 계획 | 현재 작업물 | 판단 |
|---|---|---|---|
| 모바일 패널 접속 | 같은 네트워크 접속 | 노트북 IP로 접속 확인 | 계획 충족 |
| 서버 실행 | 로컬 서버 필요 | Unreal 실행 시 서버 exe 자동 실행 구조 | 계획보다 진전 |
| 모바일 패널 배포 | Vite dev 또는 웹 패널 | `wwwroot`에 정적 빌드 반영 | 계획보다 진전 |
| QR 안내 | 필요 항목 | ASP.NET에서 URL/QR SVG/PNG 생성 | 계획보다 진전 |
| 감정/스테이지 명령 | Happy/Sad/Stage 반응 | Happy, Aged, Classic 동작 확인 | 핵심 충족 |
| 이동/회전 | 모바일 입력 제어 | 조이스틱/터치 입력 경로 존재 | 충족 |
| 데모 레벨 | 안정적인 시연 레벨 선택 | 원하는 레벨이 아니었던 이슈 발생 | 재정리 필요 |
| 운영/시연 모드 | 분리 권장 | 아직 명확한 모드 분리 없음 | 부족 |
| 텍스트 입력/AI 응답 | 향후 확장 | 아직 챗봇 미구현 | 다음 단계 |
| 데모 영상 | 1~2분 필요 | 아직 문서/영상 정리 필요 | 부족 |

## 4. 현재 프로젝트에 추가된 부분

초기 계획보다 더 추가된 부분:

- 서버 self-contained publish 방향
- Unreal 실행 시 ASP.NET 서버 자동 실행
- 모바일 패널 `dist`를 ASP.NET `wwwroot`로 배포
- 노트북 IP 기반 모바일 접속 확인
- `/api/panel/url`로 접속 URL 제공
- `/api/panel/qr.svg`, `/api/panel/qr.png`로 QR 제공
- 패키징 산출물 안에 서버를 함께 배치하는 구조
- Blue Garage 지원 분석 문서
- AI 전시 가이드 챗봇 MVP 계획 문서

이 추가분은 단순 MVP보다 포트폴리오 설명력이 좋다. 특히 “실행 파일 하나를 켜면 로컬 서버와 모바일 패널까지 함께 접근되는 전시형 시스템”이라는 설명이 가능해졌다.

## 5. 아직 부족한 부분

우선순위가 높은 부족분:

1. 패키징 경로 정합성

   현재 코드에는 서버 실행 경로 후보 탐색이 있지만, 설정 파일에는 개발/패키징 경로가 섞여 있다. 최종 패키징 폴더 기준으로 `ExhibitionServer/ExhibitionServer.exe` 또는 실제 배치 경로가 일관되어야 한다.

2. 시연 레벨 고정

   사용자가 원하는 레벨이 패키징에서 열리도록 Project Settings의 Maps & Modes, Packaging Maps 목록, Default Map 설정을 재확인해야 한다.

3. 감정/애니메이션/스테이지 연출 품질

   명령이 도착하는 것과 포트폴리오 수준의 시각 반응은 다르다. Happy, Aged, Classic, Wave, 이동/회전이 실제 데모 화면에서 명확히 보이는지 최종 확인이 필요하다.

4. 운영/시연 모드 분리

   관람객용 버튼과 개발자/운영자용 디버그 기능을 분리하면 전시 프로젝트로서 설득력이 올라간다.

5. 데모 시나리오와 영상

   기능이 있어도 보여주는 순서가 없으면 약하다. 1~2분 시연 흐름을 고정해야 한다.

6. 모바일 패널 반응형 차이

   개발 PC IP로 볼 때와 노트북 IP로 볼 때 조이스틱 크기가 달라 보였던 이슈가 있었다. 기기 DPR, viewport, 브라우저 줌, CSS rem/vw 기반 크기 차이를 점검해야 한다.

7. 챗봇/RAG 확장

   LLM Engineer 지원까지 고려하면 AI 전시 가이드 챗봇을 추가하는 것이 좋다.

## 6. 최종 MVP 완료 기준

아래를 모두 만족하면 “전시형 인터랙티브 MVP”로 볼 수 있다.

- 패키징 exe 실행
- 서버 자동 실행
- 모바일에서 QR 또는 IP로 패널 접속
- 조이스틱 이동 동작
- 터치 회전 동작
- Happy 감정 반응
- Aged/Classic 같은 스테이지 변화
- 캐릭터 인사 또는 설명 애니메이션
- 원하는 레벨로 시작
- 1~2분 시연 흐름 완성
- 노트북 단독 환경에서 재현 가능

## 7. 기술 스택

| 영역 | 사용 기술 | 역할 |
|---|---|---|
| 3D 클라이언트 | Unreal Engine 5, C++, Blueprint | 캐릭터, 애니메이션, 공간 연출 |
| 모바일 패널 | React, Vite, TypeScript | 모바일 입력 UI |
| 서버 | ASP.NET Core | 명령 수신, 패널 호스팅, QR, Unreal 중계 |

| 데이터 | JSON, DTO | 명령 계약, 전시 데이터 |
| 배포 | self-contained .NET publish, Unreal packaging | 노트북 시연 |

## 8. 권장 개발 순서

현재 기준 다음 순서가 현실적이다.

1. 패키징 경로 재확인
2. 원하는 Unreal 시작 레벨 고정
3. 패키징 exe에서 서버/패널/QR 재검증
4. Happy, Aged, Classic, Wave, 이동/회전 시연 품질 확인
5. 모바일 패널 크기 차이 점검
6. 1~2분 데모 시나리오 작성
7. 시연 영상 촬영
8. AI 전시 가이드 챗봇 구현 착수
9. RAG/LLM/structured command 추가
10. 필요 시 offline AI-generated motion 실험

## 9. 포트폴리오 포지셔닝

현재 프로젝트는 아래처럼 설명하는 것이 가장 안전하다.

```text
Unreal Engine 기반 전시 공간과 모바일 웹 패널을 ASP.NET 로컬 서버로 연결하고,
사용자 입력을 캐릭터 감정, 모션, 이동, 공간 연출 command로 변환해
실시간으로 반응하는 1캐릭터 인터랙티브 전시 프로토타입을 구현했다.
```

챗봇까지 추가하면 다음 표현이 가능하다.

```text
전시물 knowledge base와 LLM/RAG 기반 AI 가이드를 추가해,
사용자 자연어 질문을 전시 설명과 structured command로 변환하고,
검증된 명령만 Unreal 캐릭터와 전시 공간에 전달하는 AI Artist interaction system으로 확장했다.
```
